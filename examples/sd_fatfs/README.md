# sd_fatfs — два раздела MMC0, FAT и exFAT

Пример для FatFs **R0.16** из `thirdparty/ff16`. Проверяет две файловые системы
на одной microSD-карте независимо друг от друга. Предполагается MBR с двумя
основными разделами, например FAT16 на 128 МиБ и exFAT на остальном пространстве.

## Установка

Скопировать содержимое `examples/` из этого пакета поверх `examples/` проекта.
Затем перезагрузить конфигурацию CMake и выполнить чистую сборку цели
`am335x_sd_fatfs`. Это важно: настройки меняют структуры FATFS/FIL и ABI FatFs,
а `partitions.cpp` — новый исходный файл в цели.

Исправленные ранее `Card.cpp` и `Card.hpp` оставить в проекте. В этом пакете их нет.
`diskio.cpp`, аппаратный драйвер и исходники FatFs также остаются прежними.

## Настройки

| Параметр | Значение | Назначение |
|---|---:|---|
| FF_FS_EXFAT | 1 | FAT12/16/32 и exFAT |
| FF_VOLUMES | 2 | Два логических диска |
| FF_MULTI_PARTITION | 1 | Явный выбор разделов одной карты |
| FF_USE_LFN | 1 | Статический буфер длинных имён; без malloc |
| FF_LFN_UNICODE | 2 | UTF-8 в API, TCHAR остаётся char |
| FF_MAX_LFN | 255 | Максимальная длина имени |
| FF_LFN_BUF / FF_SFN_BUF | 765 / 34 | Буферы имён для UTF-8 |
| FF_STRF_ENCODE | 3 | UTF-8 для строковых функций |
| FF_LBA64 | 0 | Сохраняется 32-битный LBA существующего Card API |
| FF_USE_MKFS | 0 | Форматирование из прошивки выключено |

`ffunicode.c` уже присутствует в исходной CMake-цели. Принудительное включение
локального `ffconf.h` через `-include` сохранено. Использовать один и тот же конфиг
для `ff.c`, `ffunicode.c` и всех вызывающих файлов обязательно.

`src/partitions.cpp` содержит таблицу с C linkage:

```cpp
PARTITION VolToPart[FF_VOLUMES] =
{
    {0u, 1u}, // 0: — физический диск 0, первый раздел MBR
    {0u, 2u}  // 1: — физический диск 0, второй раздел MBR
};
```

Не менять `diskio.cpp` на два физических диска: слот MMC0 у нас один.
При увеличении FF_VOLUMES нужно расширить таблицу и обновить static_assert.
Цикл тестирования обходит FF_VOLUMES; числовые имена дисков поддерживаются FatFs
до 10 томов, но MBR предоставляет максимум четыре основных раздела.

## Поведение теста

1. Инициализирует физическую карту один раз; печатает четыре записи MBR:
   тип, начальный LBA и число секторов. Сигнатура 55AA сама по себе не доказывает
   исправность таблицы; файловую систему дополнительно проверяет f_mount.
2. Для каждого диска принудительно монтирует выбранный раздел через f_mount(...,1).
   Выводит фактический тип FAT/exFAT, начальный LBA, размер кластера, область данных
   и свободное место. Область данных немного меньше полного размера раздела.
3. Выводит корневой каталог и создаёт новый файл
   `0:/AM335X_FatFs_тест_000.txt` или `1:/AM335X_FatFs_тест_000.txt`.
   При наличии файла выбирает следующий номер, до 999. Используется FA_CREATE_NEW:
   существующие файлы не перезаписываются. Если заняты все номера, тест выдаёт ошибку.
4. Записывает текст, содержащий номер логического диска и раздела; проверяет число
   записанных байт и f_close. Повторно открывает файл, проверяет размер,
   число прочитанных байт и каждый байт содержимого. Это небольшой функциональный
   тест; объём около 135 байт, а не длительный стресс-тест.
5. Оставляет файл на карте для проверки на Linux, снова выводит каталог,
   размонтирует том и печатает PASS/FAIL.
6. Даже при ошибке первого тома пытается проверить второй. Общий успех требует
   прохождения обоих томов: `volume tests: 2/2 passed`.

При ошибке записи частично созданный тестовый файл может остаться для диагностики.
Каждый успешный запуск добавляет по файлу; их можно удалить вручную.
Никакой автоматической починки, переразметки или форматирования нет.

## Ожидаемый результат для FAT16 + exFAT

```text
0: mounted: FAT16, start LBA=..., cluster=... sectors, clusters=...
0:/AM335X_FatFs_тест_000.txt: verified 135 bytes; file left on card
0: PASS
1: mounted: exFAT, start LBA=..., cluster=... sectors, clusters=...
1:/AM335X_FatFs_тест_000.txt: verified 135 bytes; file left on card
1: PASS
volume tests: 2/2 passed
```

Тип определяется по структурам файловой системы, а не по её метке или выбранному
в программе форматирования названию. Для фактического FAT32 будет выведено FAT32.
Если один раздел отсутствует, общая проверка завершится неуспехом, даже если другой
исправен. Такой результат не означает неисправность карты.

## Границы этого этапа

- Поддерживаются FAT12/16/32 и exFAT на двух явно выбранных основных разделах MBR.
- GPT, логические разделы внутри extended-раздела и автоматический выбор тома
  без MBR в этой конфигурации не включены. Не включать FF_LBA64 без проверки
  всех преобразований LBA в существующем Card/diskio API.
- ext4 не поддерживается FatFs. Метка `root_fs` не меняет тип файловой системы.
- Тест выполняется последовательно, без RTOS и параллельных вызовов FatFs.
- Измерения задержек, большой файл и отдельный режим проверки после отключения
  питания — следующий этап. Нулевые временные метки RTT здесь не исправляются.

## Проверка перед передачей

Собраны штатные ff.c и ffunicode.c R0.16 с новым производственным ffconf.h,
новый sd_fatfs.cpp и partitions.cpp. Наш C++ код компилировался на хосте GCC
с `-std=c++17 -Wall -Wextra -Werror`.

На файловом образе MMC0 через хостовый diskio выполнены:

- FAT16 + exFAT: оба тома PASS, длинные UTF-8 имена и точное сравнение данных.
- Повторный запуск: новые файлы с номером 001, существующие не перезаписаны.
- FAT32 + exFAT: оба тома PASS.
- Преднамеренная порча читаемого содержимого: оба тома FAIL с позицией несовпадения.
- Повреждение загрузочной сигнатуры первого раздела: первый FAIL,
  второй продолжает проверку и PASS, итог 1/2.

Тестовые образы создавались отдельной хостовой утилитой. Форматирование не включено
в передаваемую прошивку. Это проверка интеграции с реальным FatFs, но не аппаратного
MMC0. При подготовке пакета ARM cross-компилятора в среде не было.
29 сентября 2026 пользователь подтвердил успешную сборку новой версии у себя;
её запуск на плате ещё ожидается. Проверка FAT12 отдельно не проводилась.

## Памятка SD: команды, ответы и последовательности

Эта часть относится к **SD Memory в обычном SD-режиме AM335x MMC0**: старт на
400 кГц с одной линией данных, затем четыре линии и 25 МГц. Для SPI есть отдельный
раздел ниже: одинаковые обозначения R1/R2 там означают другие форматы.
MMC/eMMC, SDIO, SDUC и SD Express этой памяткой не описываются.

**Обозначения:** `RCA` — адрес карты, выданный CMD3; `A(LBA)` — аргумент адреса;
`N` — число блоков; размер блока нашего API всегда 512 байт. `0` в графе аргумента
означает значение, которое передаёт наш код, в том числе вместо неиспользуемых битов.
`R1 + DATA` означает отдельный ответ на CMD и затем отдельную передачу по DAT.

### Адресация и ACMD

| Карта | OCR.CCS | Аргумент CMD17/18/24/25 | LBA 8192 |
|---|---:|---|---|
| SDSC, в том числе SD 2.0 standard capacity | 0 | `A(LBA) = LBA * 512` — байтовый адрес | `0x00400000` |
| SDHC / SDXC | 1 | `A(LBA) = LBA` — номер блока | `0x00002000` |

`Card::read_blocks()` и `write_blocks()` принимают **LBA для любой карты**.
Умножение для SDSC выполняет `m_data_address()`: снаружи повторять его нельзя.
Наличие ответа на CMD8 определяет поколение протокола, но само по себе не означает
SDHC. Тип адресации выбираем по CCS после окончания ACMD41.

**Любая ACMD — это пара команд:** сначала CMD55, затем команда с нужным индексом.
До получения RCA используем `CMD55(0)`, после — `CMD55(RCA << 16)`.
CMD55 надо повторять перед каждой ACMD, в том числе на каждой итерации ACMD41.

| Легко перепутать | На самом деле |
|---|---|
| CMD6 и ACMD6 | CMD6 переключает функции/режим скорости; ACMD6 — ширину SD-шины |
| CMD13 и ACMD13 | CMD13 возвращает Card Status; ACMD13 дополнительно передаёт 64 байта SD Status |
| CMD23 и ACMD23 | CMD23 задаёт длину следующего multi-block обмена при поддержке; ACMD23 сообщает планируемую длину записи для предварительного стирания |
| Количество блоков в MMCHS_BLK и CMD23 | Первое — настройка **контроллера**; второе — команда **карте**. Наш драйвер использует первое и Auto CMD12 |
| `0:` / `1:` и physical drive | У нас два тома одной карты: оба отображаются на physical drive 0 |

### Команды обоих примеров

`sd_blocks` вызывает `Card` напрямую; `sd_fatfs` приходит к тому же `Card` через
`diskio.cpp`. Набор команд карты у них общий. Названия методов — из нашего BSP.

| Команда | Назначение | Аргумент в нашем коде | Ответ SD | Где используется / что проверять |
|---|---|---|---|---|
| CMD0 — GO_IDLE_STATE | Начало инициализации | `0` | Нет | `m_go_idle()`; отсутствие ответа предусмотрено |
| CMD8 — SEND_IF_COND | Проверка интерфейсного напряжения и поколения SD | `0x000001AA` | R7 | `m_send_if_cond()`; `(rsp & 0xFFF) == 0x1AA` |
| CMD55 — APP_CMD | Префикс ACMD | `RCA << 16`, до RCA — `0` | R1 | `m_app_command()`; в R1 есть APP_CMD |
| ACMD41 — SD_SEND_OP_COND | Ожидание готовности, определение CCS | `0x40FF8000` после успешного CMD8; иначе `0x00FF8000` | R3 | `m_send_op_cond()`; повторять пару CMD55/ACMD41 до OCR[31]=1 |
| CMD2 — ALL_SEND_CID | Получить CID | `0` | R2, CID | `m_read_cid_and_rca()`; сохранить все четыре слова ответа |
| CMD3 — SEND_RELATIVE_ADDR | Получить RCA | `0` | R6 | Там же; `RCA = (rsp >> 16) & 0xFFFF` |
| CMD9 — SEND_CSD | Получить CSD и вычислить ёмкость | `RCA << 16` | R2, CSD | `m_read_csd()`; в нашем порядке выполняется **до CMD7** |
| CMD7 — SELECT/DESELECT_CARD | Выбрать карту для передачи | `RCA << 16` | R1b при выборе | `m_select()`; ждать завершения busy |
| ACMD6 — SET_BUS_WIDTH | Переключить карту на четыре DAT-линии | `2` после CMD55 | R1 | `m_set_bus_width_4()`; затем переключить контроллер на 4 бита |
| CMD16 — SET_BLOCKLEN | Установить блок 512 байт для SDSC | `512`, то есть `0x200` | R1 | `init()`; для обычного I/O SDHC/SDXC размер уже фиксирован 512 |
| CMD13 — SEND_STATUS | Состояние и готовность карты | `RCA << 16` | R1 | `wait_ready()` перед чтением/записью и после записи |
| CMD17 — READ_SINGLE_BLOCK | Прочитать один блок | `A(LBA)` | R1 + DATA 512 байт | `read_blocks(..., 1)` |
| CMD18 — READ_MULTIPLE_BLOCK | Прочитать несколько блоков | `A(LBA)` | R1 + DATA, N блоков | `read_blocks(..., N)` при N>1; остановка Auto CMD12 |
| CMD24 — WRITE_BLOCK | Записать один блок | `A(LBA)` | R1; затем DATA от хоста и busy | `write_blocks(..., 1)`; после передачи ещё проверяется CMD13 |
| CMD25 — WRITE_MULTIPLE_BLOCK | Записать несколько блоков | `A(LBA)` | R1; затем DATA от хоста и busy | `write_blocks(..., N)` при N>1; остановка Auto CMD12 |
| CMD12 — STOP_TRANSMISSION | Закончить multi-block обмен | `0` | R1b | В штатном пути посылается **MMCHS автоматически**, отдельного вызова `Card` нет |

В `Command::transfer()` устанавливается `auto_cmd12 = blocks > 1`.
`command_send()` программирует число блоков, multi-block, block count enable и
Auto CMD12. Поэтому искать ручной `send_command(CMD12)` в `Card.cpp` бессмысленно.

### Форматы ответов в SD-режиме

Длина ниже — **на проводе CMD**, включая служебные биты. Содержимое регистров
AM335x не равно полному кадру ответа.

| Ответ | Длина | Полезные данные | Примеры | Настройка нашего MMCHS |
|---|---:|---|---|---|
| Нет | — | — | CMD0 | `RSP_NONE` |
| R1 | 48 бит | Card Status, 32 бита | CMD13, CMD17, CMD24, CMD55 | `RSP_48BIT`, CRC и индекс проверяются |
| R1b | 48 бит + busy на DAT0 | Как R1; ждать отпускания DAT0 | Выбор CMD7, CMD12 | `RSP_48BIT_BUSY`; для команды без DATA `send_command()` ждёт TC |
| R2 | 136 бит | CID или CSD, 128 бит | CMD2, CMD9 | `RSP_136BIT`; CRC проверяется, индекс — нет |
| R3 | 48 бит | OCR, 32 бита | ACMD41 | `Command::unchecked(..., RSP_48BIT)`: CRC и индекс выключены |
| R6 | 48 бит | RCA в старших 16 битах, сокращённый статус в младших | CMD3 | `RSP_48BIT`; младшую половину нельзя декодировать как полный R1 |
| R7 | 48 бит | Код напряжения и эхо тестового байта | CMD8 | `RSP_48BIT`; ожидается эхо `0x1AA` в младших 12 битах |

Имя `response_get_r1()` в BSP историческое: метод читает `RSP10`, в котором
для коротких ответов бывает не только R1, но и OCR/R6/R7. Смысл слова определяется
последней командой.

У R6 биты 15, 14, 13 обозначают COM_CRC_ERROR, ILLEGAL_COMMAND, ERROR;
состояние остаётся в [12:9], READY_FOR_DATA — в [8]. RCA извлекается отдельно.
Регистр ответа надо сохранить до следующей команды, которая может его заменить.

### R1: статус и состояния карты

Сначала разделяем **поля состояния** и **флаги ошибок**. Ненулевой R1 совершенно
не обязательно означает ошибку.

| Биты R1 | Поле | Как читать |
|---|---|---|
| [12:9] | CURRENT_STATE | `(r1 >> 9) & 0xF` |
| [8] | READY_FOR_DATA | `(r1 & 0x100) != 0` |
| [5] | APP_CMD | `r1 & 0x20`: признак контекста application command |
| [25] | CARD_IS_LOCKED | Карта заблокирована паролем; это не механический WP-переключатель |

| CURRENT_STATE | Имя | Смысл для отладки |
|---:|---|---|
| 0 | IDLE | После сброса, инициализация ещё не завершена |
| 1 | READY | ACMD41 завершена |
| 2 | IDENT | Идентификация после CMD2 |
| 3 | STBY | RCA получен, карта пока не выбрана |
| 4 | TRAN | Нормальное состояние для запуска обмена |
| 5 | DATA | Карта передаёт данные хосту |
| 6 | RCV | Карта принимает данные |
| 7 | PRG | Внутреннее программирование |
| 8 | DIS | Отключённое состояние во время программирования |

В `wait_ready()` сейчас используется условие:

```cpp
const uint32_t state = (status >> 9) & 0xFu;
const bool ready = (state != 7u) && ((status & (1u << 8)) != 0u);
```

Перед ним проверяется маска ошибок `R1_ERROR_MASK`. Это точное описание текущего
кода, а не универсальная проверка всех допустимых переходов SD. Для запуска обычного
обмена ожидаем TRAN; текущий код **не требует явно `state == 4`**.

| Пример R1 | Расшифровка |
|---|---|
| `0x00000900` | TRAN=4, READY_FOR_DATA=1, показанные флаги ошибок отсутствуют |
| `0x00000920` | То же плюс APP_CMD; это не ошибка только из-за бита 5 |
| `0x00000E00` | PRG=7, READY_FOR_DATA=0; продолжать ограниченное ожидание |
| `0x00400900` | ILLEGAL_COMMAND плюс TRAN/READY; готовность не отменяет ошибку |
| `0x80000900` | OUT_OF_RANGE плюс TRAN/READY; проверить адрес и SDSC/SDHC |

Примеры иллюстративные: не сравнивать весь R1 с одним «магическим» числом.
Часть статусных флагов имеет собственные правила очистки, поэтому сохранять
исходный ответ в диагностике полезнее, чем печатать только название ошибки.

| Бит | Флаг ошибки R1 | Первая проверка |
|---:|---|---|
| 31 | OUT_OF_RANGE | LBA, ёмкость, перевод в байтовый адрес |
| 30 | ADDRESS_ERROR | Выравнивание адреса |
| 29 | BLOCK_LEN_ERROR | Размер блока и CMD16 |
| 28 | ERASE_SEQ_ERROR | Порядок команд стирания |
| 27 | ERASE_PARAM | Границы/параметры стирания |
| 26 | WP_VIOLATION | Защита записи |
| 24 | LOCK_UNLOCK_FAILED | Парольная операция |
| 23 | COM_CRC_ERROR | Карта отвергла CRC команды |
| 22 | ILLEGAL_COMMAND | Режим, состояние, поддержка, забытый CMD55 |
| 21 | CARD_ECC_FAILED | Внутренняя коррекция данных не справилась |
| 20 | CC_ERROR | Внутренняя ошибка контроллера карты |
| 19 | ERROR | Общая ошибка карты |
| 16 | CSD_OVERWRITE | Недопустимое изменение CSD |
| 15 | WP_ERASE_SKIP | Защищённая область пропущена при стирании |
| 3 | AKE_SEQ_ERROR | Ошибка последовательности аутентификации |

Это рабочая выборка полей, а не полный декодер всех расширений стандарта.
COM_CRC_ERROR в R1 сообщает **карта** о принятой команде; CCRC в MMCHS_STAT
сообщает **хост** о принятом ответе. Их не следует смешивать.

### Инициализация MMC0 и карты

Последовательность ниже соответствует `sd_blocks`, `disk_initialize()` и
`Card::init()` нашего BSP. Ошибка шага прекращает инициализацию.

| Шаг | Действие | Что должно получиться |
|---:|---|---|
| 1 | Настроить pinmux, тактирование, питание и MMCHS через `g_mmc0.init(cfg)` | 400 кГц, WIDTH_1BIT, конфигурация напряжения платы |
| 2 | `send_init_stream()` | Стартовая последовательность 80 тактов в нашем контроллере |
| 3 | CMD0(0) | Начальное состояние; ответ не запрашивается |
| 4 | CMD8(0x1AA) | R7 с эхо; native CMD_TIMEOUT допускается для старой SD, прочие ошибки не игнорируются |
| 5 | Повторять CMD55(0), ACMD41(...) | OCR[31] становится 1; только теперь определяем CCS |
| 6 | CMD2(0) | Сохранить CID |
| 7 | CMD3(0) | Извлечь ненулевой RCA |
| 8 | CMD9(RCA<<16) | Сохранить CSD, определить формат и число 512-байтных блоков |
| 9 | CMD7(RCA<<16) | Выбрать карту; дождаться busy release |
| 10 | CMD55(RCA<<16), ACMD6(2) | Сначала карта принимает 4-bit; затем хост включает WIDTH_4BIT |
| 11 | CMD16(512), настройка MMCHS_BLK | Наш программный размер блока — 512 |
| 12 | `bus_freq_set(..., 25000000)` | Переход на 25 МГц; это **не** включение High Speed через CMD6 |
| 13 | `m_initialized = true` | Можно использовать блочное API |

При `wide=false` шаг 10 пропускается. Для более универсального драйвера перед
выбором ширины стоит читать SCR; текущая реализация ACMD51 не посылает.
Ожидания ACMD41/CMD13 в текущем коде ограничены **числом итераций**, а не точным
таймером в миллисекундах. Нельзя принимать имя константы или количество циклов
за гарантированную длительность на любой частоте CPU.

#### OCR: что запомнить

| Поле | В аргументе ACMD41 | В ответе R3/OCR |
|---|---|---|
| [31] | Не выставляем как признак готовности хоста | 0 — карта ещё запускается; 1 — закончила запуск |
| [30] | HCS: хост умеет high capacity | CCS: карта использует блочную адресацию, когда запуск завершён |
| [23:15] | Поддерживаемое окно VDD, у нас `0x00FF8000` | Поддерживаемое картой окно напряжений |
| [24] | S18R — запрос перехода на 1,8 В, у нас 0 | S18A — принятие запроса; UHS-переход у нас не реализован |

Примерные готовые ответы: `0x80FF8000` для SDSC и `0xC0FF8000` для SDHC/SDXC.
Это не шаблоны для полного равенства: проверять нужные биты и совместимость VDD.
R7 с `0x1AA` тоже не требует перехода на 1,8 В.

### Чтение и запись в нашем драйвере

Перед обоими направлениями `Card` проверяет инициализацию, указатель, N>0 и
границы диапазона относительно `block_count()`. Адреса в API — абсолютные LBA
физической карты, не смещения относительно раздела.

| Операция | Последовательность |
|---|---|
| Один блок чтения | CMD13 до готовности → настроить 512 Б → CMD17(A) → получить R1 → `data_read(512)` → дождаться TC |
| N блоков чтения | CMD13 → настроить 512 Б и N → CMD18(A) → R1 → N раз `data_read(512)` → Auto CMD12 → TC |
| Один блок записи | CMD13 → настроить 512 Б → CMD24(A) → R1 → `data_write(512)` → TC → CMD13 до готовности |
| N блоков записи | CMD13 → настроить 512 Б и N → CMD25(A) → R1 → N раз `data_write(512)` → Auto CMD12 → TC → CMD13 до готовности |

`CC` означает окончание командной части. Это **не** завершение DATA и тем более
не основание немедленно выключать питание после записи. `TC` — событие завершения
передачи контроллера; наш код дополнительно вызывает `wait_ready()` после записи.

Для невыровненного буфера `Card` использует `m_bounce` размером 512 Б. При чтении
копирует из него в пользовательский буфер; при записи сначала копирует в него.
Команды на проводе от этого не меняются. В текущих примерах используется PIO,
не EDMA; проверку coherency DMA-кэша эти тесты не выполняют.

При ошибке multi-block передачи нельзя считать все N блоков успешно обработанными
или просто продолжать с того же места. Надо сохранить LBA/счётчик/статусы,
восстановить состояние контроллера и карты; это отдельная процедура восстановления,
которой приведённая штатная последовательность не заменяет.

#### Выбор, снятие выбора и отключение

- `CMD7(RCA<<16)` выбирает карту; ждать R1b и busy release.
- В однокарточной конфигурации `CMD7(0)` снимает выбор. Для такого случая не ждать
  обязательного ответа от карты, адрес которой не совпал.
- `f_close()` / `f_sync()` и `CTRL_SYNC` относятся к завершению файловых операций.
  Одного `f_mount(nullptr, ...)` недостаточно для сохранения незакрытых файлов.
- Для проверки сохранности: записать → проверить `f_close`/синхронизацию → дождаться
  готовности → выключить питание → включить → только читать и сравнивать.

Практические ограничения для нашего BSP:

- Параметры UHS/1,8 В нельзя добавлять одной командой: нужны подходящая плата,
  согласованный переход напряжения, режим контроллера и при необходимости tuning.
- CMD23 не следует считать обязательным у всякой старой SD; поддержка проверяется
  по SCR. Наша рабочая альтернатива — MMCHS block count + Auto CMD12.
- ACMD23 не заменяет завершение CMD25 через CMD12 в текущем native SD-пути.
- CMD28/29/30 не являются универсальной защитой всех SDHC/SDXC.
- Для erase/lock/program-CSD нужен отдельный осознанный сценарий: это не команды
  безвредной диагностики. `f_unlink()` удаляет файл в ФС и не тождествен CMD38.
- Номер `CMD1` не заменяет SD-последовательность CMD55/ACMD41; это прежде всего
  команда инициализации MMC. MMC в текущем `Card::init()` не реализована.

Для расширения нашего слоя `Command::transfer()` тоже недостаточно просто сменить
индекс: он рассчитан на обычные блоки примеров. У SCR/SD Status/switch-status свои
размеры DATA, а у некоторых операций иные требования к busy/завершению.

### Отличия SPI для nRF52

Это справка о протоколе; **SPI-драйвер не входит в текущий BSP-пример MMC0**.
Для сверки со старым аудиогидом нужны его SPI-код и разводка питания/CS.

| Что сравниваем | AM335x, native SD | SD через SPI |
|---|---|---|
| Сигналы | CMD, CLK, DAT0…DAT3 | CS, SCK, MOSI, MISO |
| R1 | 48-битный кадр, 32 бита Card Status | Один байт флагов |
| R2 | 136-битный кадр CID/CSD | Два байта статуса, например CMD13 |
| R3 | OCR в коротком кадре, ACMD41 | R1-байт + 4 байта OCR, CMD58 |
| R7 | Эхо CMD8 в коротком кадре | R1-байт + 4 байта эхо CMD8 |
| CID/CSD | CMD2/CMD9, ответ R2 | CMD10/CMD9, R1 и блок данных 16 Б |
| Адрес карты | RCA, CMD3/CMD7 | Карта выбирается CS; такого RCA-пути нет |
| Готовность при запуске | OCR[31] в ACMD41 | Сброс idle-бита R1 от ACMD41 |
| Определение CCS | OCR от ACMD41 | OCR от CMD58 после инициализации |
| Остановка CMD18 | В нашем драйвере Auto CMD12 | CMD12, с учётом дополнительного stuff-байта |
| Штатная остановка CMD25 | Auto CMD12 | Stop Tran token `0xFD` |
| Busy | DAT0 удерживается низким | Нули на MISO; хост продолжает подавать такты |

#### Короткая SPI-последовательность запуска

1. После стабилизации питания: CS=1, MOSI=1, подать минимум 74 такта на стартовой
   частоте не выше 400 кГц.
2. Выбрать карту CS=0; CMD0(0), CRC/end byte `0x95`; ждать SPI R1 `0x01`.
3. CMD8(0x1AA), CRC/end byte `0x87`; для SD v2 проверить R7 и эхо.
   Старая карта обычно сообщает ILLEGAL_COMMAND: не читать вслед за этим
   несуществующий хвост R7 как правильные данные.
4. Повторять CMD55 + ACMD41 с HCS для SD v2 до R1 `0x00`, с конечным тайм-аутом.
5. CMD58 → R3; проверить OCR, определить CCS и тип адресации.
6. Для SDSC задать CMD16(512); затем повысить SPI-частоту в пределах возможностей
   карты и платы. Повторная инициализация не должна подменять ожидание записи.

В SPI CMD58 — READ_OCR, CMD59 — CRC_ON_OFF (аргумент 0/1, ответ R1).
В native SD наших примеров эти две команды не используются.
CRC-байты кадра/данных нельзя путать с payload; выключенная проверка не означает,
что соответствующие байты можно пропускать при чтении потока.

| Маска SPI R1 | Значение |
|---|---|
| `0x01` | Idle |
| `0x02` | Erase reset |
| `0x04` | Illegal command |
| `0x08` | CRC error |
| `0x10` | Erase sequence error |
| `0x20` | Address error |
| `0x40` | Parameter error |

`0x00` — нет флагов; `0x01` — ожидаемый idle; `0x05` — idle + illegal command.
Поток `0xFF` при ожидании — **не успешный R1**: корректный R1 начинается с нулевого
старшего бита, а ожидание ответа должно иметь предел.

| SPI-токен | Где встречается |
|---|---|
| `0xFE` | Начало блока чтения; начало single-block записи |
| `0xFC` | Начало очередного блока multi-block записи |
| `0xFD` | Штатное окончание multi-block записи |
| `(token & 0x1F) == 0x05` | Data response: блок принят |
| `(token & 0x1F) == 0x0B` | Data response: CRC error |
| `(token & 0x1F) == 0x0D` | Data response: write error |

Принятый блок (`0x05`) ещё не означает, что программирование завершено.
После токена проверяется busy; затем полезен CMD13 (в SPI ответ R2), поскольку
часть ошибок проявляется во время внутренней записи.

### Ошибки на трёх уровнях

| Уровень | Что это | Где искать |
|---|---|---|
| Карта | R1/R6, OCR, состояние/busy | Ответ на конкретную команду |
| Контроллер/драйвер | MMCHS_STAT и `HAL::MMCSD::Status` | `send_command`, DATA, `wait_transfer_complete`, `wait_ready` |
| Файловая система | `DRESULT`, затем `FRESULT` | diskio и вызовы FatFs |

`FR_OK` — не содержимое ответа R1; `CMD_TIMEOUT` — не бит OCR.
Разные ошибки нижнего уровня могут преобразоваться в один `FR_DISK_ERR`, поэтому
в RTT нужен и исходный лог `sd_disk`, а не только итог `fatfs`.

| HAL Status | Интерпретация в BSP |
|---|---|
| OK | Проверенный этап завершился без обнаруженной ошибки |
| NOT_INITIALIZED | Ещё нет инициализации/адреса карты |
| BAD_ARGUMENT | Указатель, число блоков либо диапазон недопустим |
| TIMEOUT | Закончился программный бюджет ожидания CC/TC или готовности |
| CMD_TIMEOUT | Контроллер не получил ответ; для старой SD на CMD8 это предусмотренный путь |
| CMD_ERROR | Ошибка CRC/индекса/end bit командного ответа либо общий командный сбой |
| DATA_TIMEOUT | Тайм-аут DATA/busy со стороны контроллера |
| DATA_ERROR | Ошибка CRC/end bit в передаче данных |
| CARD_ERROR | CERR контроллера либо ошибка R1, обнаруженная `wait_ready()` |

| MMCHS_STAT | Бит | Смысл |
|---|---:|---|
| CC | 0 | Командная часть завершилась |
| TC | 1 | Передача завершилась |
| BWR | 4 | Буфер готов принять данные от CPU |
| BRR | 5 | Буфер готов отдать данные CPU |
| ERRI | 15 | Сводный индикатор ошибки |
| CTO / CCRC / CEB / CIE | 16 / 17 / 18 / 19 | Тайм-аут / CRC / end bit / индекс ответа |
| DTO / DCRC / DEB | 20 / 21 / 22 | Тайм-аут / CRC / end bit данных |
| ACE | 24 | Ошибка Auto CMD12; дополнительно смотреть AC12 |
| CERR | 28 | Ошибка статуса карты согласно настройке CSRE |

События STAT очищаются записью единиц в соответствующие биты. Текущий обработчик
часть событий очищает и сбрасывает линии CMD/DAT: если нужен подробный журнал,
снимок STAT/RSP/AC12 следует делать **до очистки**. Наличие поля в таблице не
означает, что наш драйвер уже выводит его отдельной строкой.

| FatFs | Практический смысл |
|---|---|
| FR_OK | Вызов успешен; для f_read/f_write ещё проверить число байт |
| FR_DISK_ERR | Ошибка блочного I/O; смотреть лог драйвера |
| FR_NOT_READY | Физический носитель не готов/не инициализируется |
| FR_NO_FILESYSTEM | На выбранном разделе не распознана поддерживаемая ФС; это не доказательство поломки карты |
| FR_INVALID_DRIVE | Номер тома/настройка FF_VOLUMES |
| FR_NO_FILE / FR_NO_PATH | Нет файла / компонента пути |
| FR_EXIST | FA_CREATE_NEW нашёл существующее имя; пример выбирает следующий номер |
| FR_DENIED | Операция запрещена, например из-за атрибута или нехватки ресурса |
| FR_WRITE_PROTECTED | Носитель объявлен защищённым от записи |
| FR_INVALID_NAME | Неправильный путь/кодировка |
| FR_INT_ERR | Внутренняя несогласованность; проверить ФС, память и ABI конфигурации |
| FR_INVALID_OBJECT | Неверный/устаревший FIL/DIR, в том числе после перемонтирования |
| FR_TIMEOUT | В частности ожидание блокировки при reentrant-конфигурации; не синоним SD DATA_TIMEOUT |

`f_read()` с FR_OK и коротким результатом может означать EOF.
`f_write()` с FR_OK и коротким результатом может означать заполненный том.
В нашем тесте ожидается точная длина, поэтому оба случая считаются неуспехом.

Минимальная диагностическая запись: номер CMD/ACMD, аргумент, физический LBA,
N, тип ответа, сырые RSP, STAT, AC12 для multi-block, длительность ожидания и
этап операции. Для ACMD сохранять также результат предшествующего CMD55.

### CSD/CID на AM335x: исправление, которое нельзя потерять

По AM335x TRM, таблица 18-13, для R2 сохраняется `RESP[127:0]`:

| Наш массив | Регистр MMCHS | Биты CSD/CID |
|---|---|---|
| `[0]` | RSP10 | [31:0] |
| `[1]` | RSP32 | [63:32] |
| `[2]` | RSP54 | [95:64] |
| `[3]` | RSP76 | [127:96] |

**Не вычитать 8 из номеров битов.** Это и было причиной «954 блока» у 32-ГБ карты.
`response_get()` читает регистры правильно, дополнительный сдвиг там не нужен.
Для коротких ответов RSP10 содержит полезное поле `RESP[39:8]`, а не весь кадр.

```cpp
const uint32_t csd_structure = (csd[3] >> 30) & 3u;

// CSD v2: SDHC/SDXC
const uint32_t c_size_v2 = ((csd[2] & 0x3Fu) << 16) | (csd[1] >> 16);
const uint64_t blocks_v2 = (static_cast<uint64_t>(c_size_v2) + 1u) * 1024u;

// CSD v1: SDSC
const uint32_t c_size_v1 = ((csd[2] & 0x3FFu) << 2) | (csd[1] >> 30);
const uint32_t c_size_mult = (csd[1] >> 15) & 7u;
const uint32_t read_bl_len = (csd[2] >> 16) & 0xFu;
const uint64_t bytes_v1 = (static_cast<uint64_t>(c_size_v1) + 1u)
                          << (c_size_mult + 2u + read_bl_len);
const uint64_t blocks_v1 = bytes_v1 / 512u;
```

Это памятка по вычислениям, не замена всей функции: выбирать только подходящую
ветку, отвергать неизвестную структуру и проверять поля/диапазоны. Промежуточный
`uint64_t` защищает вычисление от переполнения; перед сохранением результата в
нынешний `uint32_t m_block_count` нужна проверка представимости. Ровно 2^32 блоков
этим полем не представляются, даже если отдельный LBA ещё 32-битный.

Имя продукта — CID[103:64]: младший байт `cid[3]`, затем четыре байта `cid[2]`
от старшего к младшему. Строка имени не является надёжным кодом ёмкости.

Подтверждённые нашими запусками значения:

| Карта | Определение | Блоков | МиБ |
|---|---|---:|---:|
| Номинально 32 ГБ | SDHC/SDXC, EB1QT | 62 521 344 | 30 528 |
| Номинально 2 ГБ | SD 2.0 standard capacity, SD16G | 3 903 488 | 1 906 |

CID/CSD и ёмкость карты не меняются от выбора FAT16/FAT32/exFAT.
Разделы и файловая система лежат внутри пользовательских секторов.

### Что происходит под вызовами FatFs

Карта не получает команду «открыть файл». FatFs разбирает каталоги, FAT или
структуры exFAT и переводит действия с файлами в обращения к секторам.
Фиксированного соответствия «один f_read = один CMD17» нет: влияют размер запроса,
выравнивание, границы кластеров и буферы FatFs.

| Вызов / этап | Что делает слой выше Card |
|---|---|
| `report_mbr()` | Вызывает disk_initialize(0), читает LBA 0 и печатает записи MBR |
| `f_mount(..., 1)` | Регистрирует FATFS, принудительно распознаёт выбранный том; при необходимости инициирует disk_initialize |
| `f_getfree()` | Получает свободные кластеры; может читать служебные структуры и выполнять заметный объём I/O |
| `f_opendir()` / `f_readdir()` | Читает каталог и связанные служебные данные |
| `f_open()` | Находит/создаёт запись файла; при создании возможны записи метаданных |
| `f_read()` | Получает содержимое через буферы и disk_read |
| `f_write()` | Записывает/буферизует данные и изменяет служебные структуры |
| `f_sync()` / `f_close()` | Сбрасывает изменения файла; проверять результат |
| `disk_read(..., 1)` / `disk_read(..., N)` | Доходит до CMD17 / CMD18 через Card |
| `disk_write(..., 1)` / `disk_write(..., N)` | Доходит до CMD24 / CMD25 через Card |
| `disk_ioctl(CTRL_SYNC)` | В нашем порте вызывает `g_card.wait_ready()` |
| `f_mount(nullptr, drive, 0)` | Снимает регистрацию тома; открытые файлы надо закрыть заранее |

Начальный LBA раздела учитывает **FatFs**. `disk_read` и `disk_write` получают уже
физический LBA; прибавлять туда начало раздела повторно нельзя.
`0x55AA` не различает MBR и загрузочный сектор файловой системы и не доказывает
исправность ни одного из них. Тип ФС определяется по её структурам, а не одной
сигнатуре или метке тома.

### Контрольный список перед запуском

- Правильный физический диск и выбранные записи `VolToPart`.
- Один `ffconf.h` для всего проекта и чистая пересборка после изменения настроек.
- Для SDSC байтовый адрес формируется ровно один раз внутри `Card`.
- CMD55 непосредственно перед каждой ACMD.
- R3 не проверяется как CRC-защищённый R1.
- CSD/CID AM335x декодируются без сдвига на 8 бит.
- После записи проверяются и число байт, и результат закрытия, и готовность.
- Auto CMD12 учитывается при отладке нескольких блоков.
- Сырые статусы сохраняются до очистки; ожидания ограничены.
- Успешное немедленное чтение не заменяет тест после отключения питания.
